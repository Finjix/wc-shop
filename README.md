# WC Shop

微信商城小程序，配套 React 管理后台和 CloudBase 云函数。支持微信支付 APIv3 下单、查单、通知验签解密及退款；本地开发保留模拟支付。收货地址保存在客户端本地。真实支付上线前须完成下方配置与验收。

## 本地开发

后台和小程序的显示版本号共用 `miniprogram/config/version.ts` 中的 `APP_VERSION`。只需修改这一处，再分别重新构建并发布后台和小程序。

安装依赖：

```sh
npm ci
npm --prefix admin ci
npm --prefix cloudfunctions ci
```

1. 在微信开发者工具中导入项目，执行「工具 → 构建 npm」，再运行 `npm run build:subpackage-ui`。
2. 将 `miniprogram/config/runtime.ts` 中的 `useLocalBackend` 设为 `true`。
3. 按 `admin/.env.example` 配置 `admin/.env.local`；本地调试时设置 `VITE_LOCAL_API_URL=http://127.0.0.1:8787`，留空则连接云端。
4. Windows 下运行 `start-local.cmd`，启动本地后端（8787）和管理后台（5173）。

也可分别启动：

```sh
npm run dev:local-backend
npm --prefix admin run dev -- --host 127.0.0.1 --port 5173
```

本地数据库、上传图片和缓存统一保存在项目同级的 `../.wc-shop-local/`，本机路径为 `D:\project\.wc-shop-local`。其中 `migrations/` 存放旧数据迁移备份，请勿随意删除。不要提交真实数据或密钥。

## 物流查询

订单和退货售后的「查看物流」通过用户点击直接跳转快递100小程序查询结果页，携带运单号，由快递100识别物流公司；无需物流 API 密钥。遵循[快递100官方跳转协议](https://m.kuaidi100.com/open/miniprogram.jsp)，目标 AppID 为 `wx6885acbedba59c14`。微信会弹窗确认跳转，用户取消时保持原页。

跳转失败时在当前页面弹窗提示，不再进入本地物流页或网页。订单详情的下单时间下方显示物流单号并支持手动复制；不会自动覆盖剪贴板，也不传收货人、收货电话或地址。部分承运商查询可能还需用户在快递100内补充手机号验证。

微信基础库从 2020 年 4 月起不再要求配置 `navigateToMiniProgramAppIdList`。开发者工具不会真实打开其他小程序，需使用体验版在手机微信验收跳转、取消、返回和查询结果。公开第三方网页不能仅凭 URL 在小程序内打开，仍需满足 `web-view` 的业务域名配置要求，因此当前入口使用小程序直跳。

## 项目结构

| 目录 | 用途 |
| --- | --- |
| `miniprogram/pages/`、`miniprogram/custom-tab-bar/` | 主包：首页、分类、购物车、我的和底部导航 |
| `miniprogram/goods/` | 商品分包：列表、详情、搜索、评价 |
| `miniprogram/order/` | 订单分包：结算、订单、售后、物流 |
| `miniprogram/user/` | 用户分包：资料、地址、帮助和关于 |
| `miniprogram/services/` | 接口服务分包：请求、数据转换和共享业务状态 |
| `miniprogram/utils/` | 工具分包：图片处理和 WebP 编码 |
| `miniprogram/assets/` | 资源分包：首页固定活动 JPG 图集、默认头像和异步图片组件 |
| `design/home-promos/` | 活动图原始插画、背景、花字和生成提示词，不参与小程序上传 |
| `miniprogram/components/` | 主包公共组件 |
| `miniprogram/common/`、`miniprogram/config/` | 公共逻辑、异步服务入口、类型声明和运行配置 |
| `admin/` | React 管理后台 |
| `cloudfunctions/` | 云函数业务和服务端测试 |
| `scripts/` | 启动、构建、部署和回归测试 |

`project.config.json` 的小程序根目录为 `miniprogram/`。四个 Tab 直接运行在主包；商品、订单和用户页面按业务分包。`services` 保存接口实现和共享业务状态，通过主包异步入口统一加载并支持失败重试；`utils` 的图片编码组件由上传页面按需加载。售后转换逻辑分别放在订单、服务分包，主包不保留副本。

全局主题位于 `miniprogram/app.wxss`。各包的 `components/tdesign/` 为生成的 UI 依赖，修改组件引用后运行 `npm run build:subpackage-ui`。构建脚本将主包使用的组件留在公共目录，其余组件随业务分包放置，并裁剪未使用文件。分包可同步引用主包，分包之间使用页面跳转或声明的异步入口。

### 三级商品类别

后台「商品类别」按一级、二级、三级维护：一级显示在分类页左栏，二级在右侧按组显示标题和可选图片，具体卡片为三级类别的图片及名称。每个一级、二级类别下至少包含一个三级类别；三级图片必填，商品只可选择一个三级类别（也可暂不分类）。一级、二级、三级名称均最多 5 个字，二级类别标题使用棕色加粗样式，新增、改名及保存均校验，分类页按此上限单行完整展示，不换行、不省略或裁切。已有超长名称需在后台改名后才能保存。点击三级卡片进入该类别商品搜索结果；点击二级图片进入其全部下级商品结果，筛选、排序和分页均在分类聚合后执行。分类页不再请求或展示商品卡片。删除一级或二级会清除全部下级及商品分类关联，不删除商品、库存或订单。

商品编辑已取消分类页专用的「商品名称」，保留商品标题；旧 `name` 字段不再参与小程序展示或搜索。副封面仍可选填，仅用于商品详情页轮播，商品列表使用主封面。

本地旧分类清理需启动本地后端并暂停编辑，执行 `npm run reset:local-categories -- --confirm`。脚本先将完整本地数据库及图片备份到 `../.wc-shop-local/backups/categories-reset-*/`，再清除分类和商品分类关联，不自动添加示例分类；恢复备份前先停止本地后端。脚本只连接本地，不会清理云端或在启动/部署时自动清空新分类。云端上线需先备份数据库及文件，部署配套云函数后在后台删除旧一级类别及孤立类别，再重新创建三级结构并关联商品；仅发布前端不会清理云端数据。运行 `npm run test:categories`、`npm run test:product-names`、`npm run test:product-covers` 和 `npm run test:cloud` 验证。

商品搜索忽略空白、大小写及全角/半角差异，查询中的任意一个文字、字母或数字命中商品名称、有效分类名称或已配置规格即可返回；标点不作为正则表达式，纯空白按未输入关键词处理。匹配完成后再排序和分页。搜索结果及评价列表加载成功且为空时显示“暂无”，请求失败仍显示错误状态。

搜索结果（含分类商品结果）改为每行两张卡片，与首页「更多献礼」共用 `miniprogram/components/gift-card/index.wxml` 模板和 `miniprogram/style/gift-card.wxss` 样式，封面、两行标题、价格、圆角及购物车按钮一致。点击卡片进入详情，点击购物车进入详情并打开加购规格选择；排序、筛选和分页逻辑保留。米色背景仅限首页，搜索结果为白底，其他页面及选中态的浅色底统一使用中性灰；共享卡片的封面占位色仅在首页局部覆盖为米色，棕色文字、边框和操作按钮保留。运行 `npm run test:backgrounds` 检查背景范围。运行 `npm run test:search-cards` 检查共享模板/样式、跳转、分类参数、排序、分页及空/错误状态。

首页「邀请返现 / 加客服拿好礼」均使用普通图片节点和离散 CSS 动画播放 35 帧 JPG 图集，保持原始帧间隔和 2.5 秒循环，进入可见区域播放、滚出屏幕或离开页面暂停。图集质量分别按原 GIF 字节数自动选择，体积差异控制在 5% 内；加载失败显示静态 JPG 首帧。包内无 GIF、Canvas、逐帧 JS 定时器或额外网络/数据库请求。无损动画源文件仅保留在包外的 `design/home-promos/animations/*-source.webp`，运行 `npm run build:promo-frames` 生成两张图集、静态首帧、样式和体积清单；`npm run test:promo-frames` 检查全部帧的画面误差、时序、暂停恢复和回退。

首页原商品区已替换为固定的「倾心推荐」和「更多献礼」。后台提供四个推荐位，每位选择在售商品并上传独立的 9:16 封面；未完成的位置不展示，旧 `sections` 不自动迁入，新版保存时移除。顶部轮播图每 2.5 秒向右切换，推荐卡片每 2.5 秒向左切换；两者保留原生触摸方向，单张静态显示。更多献礼进入首页时不加载，首次向下浏览才加载 6 个，此后触底每批加载 6 个，每轮随机且轮内不重复，展示完后重新打乱循环。购物车图标进入详情后自动打开规格选择，返回首页保留浏览位置。

标题卡通图标位于资源分包 `miniprogram/assets/home/`，为透明的单张 PNG（64×64，以 64px 显示）；爱心、星星与花字使用 WXSS 动画。顶部搜索栏提示文字静态显示，后台输入和服务端保存均限制 16 个字，旧的超长文案读取时仅展示前 16 个字。运行 `npm run build:home-mascots` 可从 `design/home-showcase/` 的原画重新导出两张静态图标，原画和提示词不参与小程序打包。

首页、分类、商品搜索、列表、搜索结果和商品详情均注册好友与朋友圈分享回调，并显式开启右上角分享菜单。好友商品链接进入对应商品详情，朋友圈使用当前页面和商品查询参数；列表分享保留分类、搜索词。分享商品不携带 `skuAction` 等临时操作参数。本地存储图片地址不会作为分享封面发送。回归测试不实际发送微信消息，最终发送及接收需在真机预览或发布版本验证。

发布前将 `useLocalBackend` 改为 `false`，确认云环境和后台接口配置后执行 `npm run package:deploy`，部署包输出到 `dist/`。

## 微信支付配置与上线

当前代码默认关闭线上下单，不会因为缺少凭证而退回模拟支付。`scripts/local-backend.js` 和测试显式启用模拟支付；历史模拟订单仍只做模拟退款。

1. 在商户平台「账户中心 → API安全」准备 APIv3 密钥、商户 API 证书序列号、`apiclient_key.pem` 私钥、微信支付公钥及公钥 ID。已有业务在用的密钥不能随意重置。
2. 在 CloudBase 的 `wc-shop-function → 函数配置 → 编辑 → 环境变量` 中按 [cloudfunctions/.env.example](cloudfunctions/.env.example) 配置。PEM 可用完整文本或将换行写为字面 `\n`。后台无需访问口令，管理接口不进行登录鉴权；可访问接口的人能够修改商品、查看订单和审核真实退款。商户凭证仍只保存在云函数环境中，不放进 `VITE_*` 或客户端代码。
3. 当前已存在指向本函数的 HTTPS `/admin-api` 路由，模板使用此地址作为 `WECHAT_PAY_NOTIFY_URL`，无需另开公开路由。新代码根据 `Wechatpay-Signature` 请求头分流通知。平台必须向函数透传原始请求体及 `Wechatpay-*` 头；禁止代理层解析再序列化请求体。支付和退款通知共用此地址，仅通过 RSA 验签及 AES-GCM 解密的数据能改变账务状态。HTTP 管理请求使用 `scope: admin`，无需 Authorization 请求头。
4. 在文档型数据库中新建 `payments` 集合，设置为仅服务端可读写；确认 `orders`、`orderRequests`、`skus`、`afterSales` 等业务集合也禁止客户端直接写入。支付表保存支付单与多个业务订单的关联，金额为人民币分。
5. 函数执行超时调为 **60 秒**。创建每 5 分钟执行的定时触发器，名称 `payment-reconcile`，检查实际投递事件包含 `Type: Timer`、`TriggerName: payment-reconcile`。定时任务查单、关闭已过期未付款交易、查询已批准退款并重试发货信息上报，不发起支付扣款。退款查询只有在验签通过且返回 `RESOURCE_NOT_EXISTS` 时，才使用原退款单号和原金额重新提交。各队列每批最多 10 条，游标和轮换优先级保存在 `settings` 的 `__payment_reconcile_*` 文档中，失败记录不会一直占住队首。还可通过后台 API `payments.reconcile` 手动补偿；此操作可能重试已批准的退款。`payments.checkConfiguration` 使用随机的不存在订单号进行只读验签检查，并检查物流公司查询权限，不创建支付或退款。
6. 部署云函数和配套管理后台；在所有凭证有效、通知地址可达后把 `WECHAT_PAY_MODE` 改为 `wechat`。不要仅替换前端或仅设置模式。后台网页及标准定时器触发时没有小程序云调用凭证，必须在服务端配置 `WECHAT_APP_SECRET`，通过 `stable_token` 获取并缓存 access_token，使用普通刷新（`force_refresh: false`），不使其他业务已有令牌失效。密钥和令牌均不返回前端或写入日志。`config.json` 同时声明发货和物流列表的云调用权限，供小程序调用路径使用。真实支付订单发货时选择快递公司，由云函数上报微信订单发货管理；同一次支付的不同子订单以拆分发货方式上报。失败保留支付单上的补偿标记，由定时器重试。上线前必须确认实际接口可调用、微信后台可看到发货信息。
7. 真机验收：真实支付前仅在 `payments` 保存内部结算草稿并预留库存，不写入 `orders`，也不移除购物车商品。取消或失败可在当前结算页重试；只有微信签名查单或验签解密的回调确认支付成功，才在同一事务中生成全部正式子订单并扣除对应购物车数量。超时草稿关单并只释放一次库存，不生成“已关闭”正式订单。历史已创建的待付款/已关闭订单保留并兼容旧流程。还需验证同一结算多个 SKU 只支付一次、重复通知只建单一次、审核退款仅在微信确认成功后更新金额与库存。由商户本人完成实际付款，退款先使用明确批准的测试订单验证。

公众平台「支付与交易 → 订单管理 → 订单信息录入」的商品订单详情 path 填写 `order/order-detail/index?orderNo=${商品订单号}`。当前平台提示必须先开发订单详情页并提交小程序审核，再配置 path。占位符保持原样，微信会替换成预下单的 `out_trade_no`。云函数通过 `payments` 记录核验当前用户并映射到结算的首个业务订单；其他人的支付单号不能访问。该页面和对应代码需要包含在已发布的小程序版本中，后台配置不能替代小程序版本发布。
