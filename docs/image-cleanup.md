# 图片清理与格式迁移

后台替换、移除图片，删除分类或软删除商品/SKU后，会将原 fileID 放入浏览器持久化清理队列。保存成功后以最多五张一批请求 `storage.cleanup`。清理失败不会影响已经保存的数据，下一次保存重试。

清理会扫描全部业务集合，包括购物车、历史订单、评价和售后，共享图片有任一引用就保留。已被管理员软删除的商品/SKU不再算有效引用，历史订单中的图片快照仍算。扫描出错、超出预算或扫描期间数据发生变化，会停止清理。标记删除与业务图片写入使用同一个事务版本号，已退休的图片不能被重新引用。

生命周期版本、删除状态及旧图到新图的映射保存在现有 `settings` 集合的 `__image_*` 内部文档中。不需要新集合或“图片资源”模块。映射使仍持有旧 fileID 的客户端读取新文件、保存时自动更新引用。

一次性维护接口需具有 settings 管理权限：`storage.maintenance.references` 每次盘点一个集合的25条记录；`storage.maintenance.replace` 在事务中重读并替换指定文档的图片引用；`storage.maintenance.cleanup` 仍执行完整引用核对。浏览器在本机下载、编码及上传 WebP，云函数不处理图片像素，避免3秒执行时限。转换保留尺寸，使用 WebP quality=100、alpha_quality=100；质量100并非无损模式。
