# 图片清理与格式迁移

后台替换、移除图片，删除分类、商品、SKU、订单、评价或售后，以及用户撤回、重新申请售后后，原 fileID 会在业务事务中登记到 `settings` 的持久化清理队列。浏览器持久化队列继续兼容旧版本，清理失败不影响已保存的数据。

后台和小程序在上传前调用 `storage.prepareUpload` 取得正式路径和 fileID，并登记 24 小时租约。上传失败、取消保存或提交失败时立即核对引用后清理；页面关闭、超时或丢失响应时，服务端租约仍保留。后续访问概览或业务保存调用 `storage.cleanupQueue`，每次处理最多五张已到期文件。小程序只可处理属于当前用户的候选文件。已成功保存的共享图片会保留并移出队列。

清理会扫描全部业务集合，包括购物车、历史订单、评价和售后，共享图片有任一引用就保留。已被管理员软删除的商品/SKU不再算有效引用，历史订单中的图片快照仍算。扫描出错、超出预算或扫描期间数据发生变化，会停止清理。标记删除与业务图片写入使用同一个事务版本号，已退休的图片不能被重新引用。

生命周期版本、租约、删除状态及旧图到新图的映射保存在现有 `settings` 集合的 `__image_*` 内部文档中，不需要新集合。删除标记用于阻止旧客户端重新引用已清理文件，不能当作无用记录删除。订单删除后也保留最小幂等标记，阻止旧请求重复创建订单。

后台可直接打开 `#/maintenance`，粘贴从云存储列表盘点得到的文件路径或 fileID，先检查引用，再清理未引用文件；执行时仍会再次核对引用。该入口不自动假设上传列表等于完整存储清单。

一次性维护接口需具有 settings 管理权限：`storage.maintenance.references` 每次盘点一个集合的25条记录；`storage.maintenance.replace` 在事务中重读并替换指定文档的图片引用；`storage.maintenance.cleanup` 仍执行完整引用核对。浏览器在本机下载、编码及上传 WebP，云函数不处理图片像素，避免3秒执行时限。转换保留尺寸，使用 WebP quality=100、alpha_quality=100；质量100并非无损模式。
